Section 1

Architecture Overview

MedApp is a multi-tenant medical management platform. All data is scoped to a selected company context, and all features enforce role-based access.

⚡ Framework & State

  • Angular 17+ with standalone components
  • Signals (signal(), computed(), effect()) instead of NgRx
  • Lazy-loaded routes via loadComponent / loadChildren

🔐 Security

  • JWT token stored in session storage
  • Bearer header injected by HTTP interceptor
  • Three guards: authGuard, companyGuard, roleGuard

🏢 Multi-tenancy

  • Every resource belongs to a company
  • Active company set via CompanyContextService
  • All lists auto-reload when company changes

🎨 UX

  • Dark / Light theme toggle (persisted to localStorage)
  • Toast notifications (auto-dismiss at 3.5 s)
  • Responsive layout shell with sidebar + navbar

Organizational Hierarchy

  • 🏥 Company
    • 🏢 Area
      • 🩺 Specialty
        • 👨‍⚕️ Specialist
        • 📋 Intervention Type
    • 🧑‍🤝‍🧑 Patient

Section 3

Authentication

Handles login, session management, and post-login routing based on the user's role and company access.

Login Flow

  • Enter credentials Username and password are submitted via the login form.
  • Token issued A session token is stored in sessionStorage; the current user is held in a signal.
  • Role-based redirect Admin: → /admin/select-company  |  Non-admin (1 company): auto-sets context → /dashboard  |  Non-admin (multiple companies): → /select-company
  • Authenticated requests The HTTP interceptor attaches Authorization: Bearer <token> to every outgoing request.

Logout

Available from the navbar. Clears the session token, the company context, and redirects to /login.

Section 4

Company Selection

Before accessing any feature, a user must select the company they are operating within.

Non-Admin Selection Receptionist / Specialist

A card picker is shown listing all companies the user belongs to. Selecting one sets the company context and redirects to the dashboard.

If the user only has access to one company, this screen is skipped and the context is set automatically.

Admin Selection & Management Admin only

A full company management table with search and filter. Admins can:

  • Create a new company
  • Edit an existing company
  • Delete a company
  • Select a company to work in

Create/Edit actions open an inline modal form.

The dashboard adapts its content based on the user's role.

Specialists

Admin only   Route: /specialists

Manage the medical professionals associated with the company. Each specialist belongs to one specialty and can have a configurable weekly availability schedule.

ActionRouteDescription
List/specialistsTable with full name, license number, resolved specialty name, email, and active badge.
Create/specialists/newRegister a new specialist.
Edit/specialists/:id/editUpdate specialist details.
Availability/specialists/:id/availabilityManage the specialist's weekly schedule.
DeleteAction in listRemoves the specialist record.

Form Fields

First Name * Last Name * License Number * Specialty (dropdown) * Email * Phone Active (checkbox)

Weekly Availability Schedule

A 7-day grid (Sunday – Saturday) where administrators define the time intervals during which a specialist is available.

Add Interval

Each day has an inline "from / to" time picker. Submitting creates a new availability interval chip on that day.

View Intervals

Occupied days display colored chips for each configured time interval.

Delete Interval

Each chip has an × button to remove that specific time interval. To modify a slot, delete it and re-add with the corrected times.

The availability schedule feeds directly into the scheduling wizard's slot picker. The system generates 30-minute booking slots and excludes already-booked times in real time.

Section 13

Scheduling

Admin Receptionist Specialist   Route: /scheduling

Manage appointment bookings. A 6-step guided wizard ensures all required information is collected before confirming a booking.

Appointment List

Column / ActionDetails
PatientFull name
SpecialistFull name
InterventionProcedure name
Date & TimeScheduled date and start time
Statusscheduled completed cancelled
Mark as DoneTransitions status from scheduled → completed. Visible only on scheduled rows.
CancelTransitions status from scheduled → cancelled. Visible only on scheduled rows.
Completed and cancelled appointments are not editable or deletable — only the status can be transitioned while an appointment is in scheduled state.

6-Step Booking Wizard

  • Select Patient Searchable card list by name or document ID. If accessed via the "Schedule" button on the Patient List, the patient is pre-selected and this step is skipped.
  • Select Area Searchable card list of areas scoped to the current company.
  • Select Specialty Filtered to specialties within the chosen area. Searchable.
  • Select Procedure (Intervention) Filtered to interventions under the chosen specialty. Searchable by name or CPT code.
  • Select Specialist Filtered to specialists belonging to the chosen specialty. Loaded asynchronously. Searchable.
  • Select Date & Time Date picker (minimum date = today). Once a date is selected, 30-minute availability slots are generated from the specialist's schedule with already-booked slots excluded. Unavailable slots are shown but disabled.
At every step, a breadcrumb context bar displays previous selections with "Change" buttons to go back and update a choice — automatically clearing all downstream selections.
